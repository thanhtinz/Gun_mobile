# Defect inventory — subsystems audited against the PC dump

Two passes of a 6-agent audit workflow over the extracted Ok dump, then an
adversarial verifier on every finding claimed to affect shipped behaviour.
Each agent reimplemented a shipped reader's logic, ran it across every matching
file in the dump beside an implementation written from the format, and counted
the disagreements — the method that found the eight bugs fixed on this branch.

The dump is not in the repo (4.4GB; the archives are LFS pointers), so this file
is the record. `tools/audit_readers.py` re-derives the invariants behind the
fixes; this inventory is the list of what is still wrong.

## Correction: the PC physics ground truth is in the dump after all

An earlier revision of this file stated three times that `game.logic.dll` is
absent from the dump — in the ballistics *Method* note, in a *checked and
correct* entry, and, load-bearingly, as a reason for **refuting** a finding.
**All three were wrong.**

`ex3/Service/Fight/Fighting.Service.exe` is a Costura bundle. The raw-deflate
blob at offset 796153 inflates to an 824832-byte PE — `game.logic.dll` —
carrying `SimpleBomb`, `Physics`, `Wind`, and the strings `bomb\{0}.bomb` and
`{0}/{1}.bomb`. Those strings are UTF-16LE, which is why an ASCII grep over the
dump missed them and the searches were reported as exhaustive when they were not.

Disassembling it gives the PC integrator directly, and its inputs check out
against shipped data without trusting the IL:

| | |
|---|---|
| `BombObject.UpdateAGW` | `m_gf = map.gravity * gravityFactor * mass` |
| `Map.get_gravity` | `MapInfo.Weight` — **10 on 545 of 546 maps** (`LoadMapsItems.xml`) |
| `SimpleBomb..ctor` | `gravityFactor = BallInfo.Weight` — **70 on 1937 of 1937 balls** |
| `Map.get_airResistance` | `MapInfo.DragIndex` — **2 on all 546 maps**; the port has no drag at all |
| `StartMoving` | `CompleteNextMovePoint(0.04f)` — dt = 40ms, matching the 25fps config |

So PC gravity is 10 × 70 = 700 px/s² = **1.12 px/frame²**, against the port's
0.7 × 0.70 = 0.49, and the PC applies air drag the port omits entirely.

**Two refutations therefore rest on a false premise and are reopened:** the
`Weight=70` gravity finding (pass 1) and the `WindAccelPerFrame` finding
(pass 2) were both dismissed partly on "there is no ground truth anywhere".
There is. Their other grounds — that the headline impact figures came from
simulating past the bounds check the code enforces — still stand and are
unaffected; it is only the no-source argument that fails. Treat both as open.
